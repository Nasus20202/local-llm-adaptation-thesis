## Why

The accepted Kubernetes benchmark policy cannot progress to development-only construction until item metadata, evaluator calibration, contamination auditing, and the proposed `kind`/official-web conditions have deterministic software contracts. Without those contracts, pilot evidence would be incomparable, leak-prone, or impossible to audit.

## What Changes

- Add a development-only benchmark manifest and validation capability that preserves scenario-family grouping, language/task balance, protected golden boundaries, metric applicability, and contamination-review state.
- Add evaluator fixtures, deterministic outcome records, blinded human-rating imports, adjudication, calibration summaries, and immutable evaluation-version behavior.
- Add a neutral, allowlisted `kind` execution boundary with reset, egress/permission probes, action capture, and final-state validation for a separately gated interactive stratum.
- Add a separately identified official-source W1 search/fetch boundary with strict allowlisting, budgets, complete provenance, and benchmark-repository denial controls.
- Add pilot progression reporting for `GO`, `AMEND`, and `STOP/DEFER` without implementing model inference, constructing benchmark payloads, or using final-test outcomes.

## Capabilities

### New Capabilities

- `benchmark-pilot-dataset`: Development-only family metadata, protected-content boundaries, applicability, overlap-audit records, and pilot progression inputs.
- `evaluation-protocol`: Versioned deterministic evaluators, fixture outcomes, blinded human ratings, adjudication, calibration, and derived evaluation records.
- `controlled-cluster-tasks`: Neutral resettable `kind` task execution with matched permissions, isolation checks, complete actions, and deterministic final-state validation.
- `web-search-sensitivity`: Separately governed W1 official-source search/fetch with enforced access controls, budgets, captures, and reproducibility metadata.

### Modified Capabilities

None. Integration with the existing experiment runner and run-provenance capabilities remains outside this change because the foundation intentionally does not execute or record model observations.

## Impact

The implementation will add small typed schemas, pure validation/evaluation logic, fixture-driven tests, and narrowly scoped external-process adapters for `kind` and W1 feasibility checks. It will not add stable CLI integration, model inference, RAG, fine-tuning, a production agent framework, benchmark/golden payloads, or final-test access. Routine CI will use synthetic fixtures and fakes; real clusters, web access, and model execution remain opt-in.
